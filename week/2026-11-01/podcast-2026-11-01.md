Alex: Anand's Weekly Codecast. Week ending 01 November 2026. This week’s code has a recurring question: when does an automation know it has enough evidence to act?
Maya: That question turns up in places you might not expect: a WhatsApp history backup, a phone-based translation tool, and a new remote control for presenting browser tabs.
Alex: Start with the backup. A chat archive can look complete because it has messages from the top and bottom, while silently missing the middle.
Maya: That was the trap. WhatsApp virtualizes its message list: it only renders the messages around the current scroll position. Jumping straight to the top can skip what never appeared on screen.
Alex: So the fix is more like walking down a staircase than teleporting between floors. The scan scrolls through overlapping viewports, giving the page time to render the messages between them.
Maya: And the backup now refuses to pretend a partial scan is complete. If WhatsApp cannot load earlier messages, or the scan hits its round limit, that conversation stays unchanged and the run reports why.
Alex: The limit rose from 200 to 2,000 scroll rounds. That gives large groups room to load, but the important safeguard is not the bigger number; it is the explicit failure state.
Maya: There’s also a practical image change: available images are exported by default, with `--no-images` to opt out. The code checks the data before saving, rather than trusting every string that looks like an image.
Alex: I like that the correction is not just “scroll more.” It distinguishes a plateau from a visible “Load earlier messages” control that isn’t working. That gives the person running the backup a clue about what to fix.
Maya: Another new tool takes the same idea of preserving a clear boundary into live speech translation. It creates a virtual microphone, so a meeting app can receive translated speech as if it came from a normal mic.
Alex: The implementation uses Gemini’s live translation API over WebSockets, then sends audio through a PipeWire virtual device. So the chain is: microphone in, translated audio out, and the meeting app sees a selectable input.
Maya: It can switch target languages while running, and it tells you that choosing a voice does not guarantee Gemini will keep using that voice. That is a useful limit to state, not hide behind a settings menu.
Alex: There is an “off” mode, too, so the original voice can pass through until translation is turned back on. I’m curious about the practical failure: a virtual microphone is only useful if the target app selects it correctly.
Maya: True, and that is why the project includes status and device selection rather than treating audio routing as magic. It is still a Linux-focused tool; it is not evidence of a polished, cross-platform meeting product.
Alex: The other presentation utility goes the opposite direction: your phone becomes a remote for Edge tabs. A small local server talks to the browser through CDP, the Chrome DevTools Protocol.
Maya: The phone is designed as a blind trackpad: you watch the projected page, not the phone screen. Tailscale Serve provides HTTPS access, but the browser’s debugging endpoint stays local and is never exposed to the network.
Alex: That’s a sensible separation. The remote can scroll, zoom, switch tabs, and save viewpoints, while CDP remains behind the local machine. The `check` command also tests the connection to the phone and reports whether Tailscale is relaying it.
Maya: And the work included a small but revealing usability repair: the first dark interface was hard to see, and full-screen mode made it unclear how to escape. The page now supports a light theme and avoids forcing full screen.
Alex: There’s a new `edge import` command as well. It reads links from Markdown, groups them using nearby headings or parent list items, and opens them as tabs in a new Edge window.
Maya: The test checks three different Markdown layouts that all describe the same group of links. That is a good test of intent: accept flexible human notes without silently mis-grouping the tabs.
Alex: And a cluster of smaller maintenance changes makes these scripts easier to trust: a compressed Codex session format is now readable, with `zstandard` on older Python and the built-in `compression.zstd` on newer versions.
Maya: The development guidance now says to wait for the specific screen or response you need, rather than `networkidle`, which can hang on long-lived requests. It also adds a `just verify` convention for running the suite before shipping.
Alex: That is less glamorous than a new remote, but it is the same theme: do not mark the operation done just because the tool stopped moving. Check the observable result.
Maya: And the video-email converter now uses a video’s `poster` image as a clickable preview. Email clients often cannot play embedded video, so a still image gives the reader a usable link instead of a blank spot.

Alex: That same caution about partial success matters for the new Android sync tool. It began as a separate experiment and then moved into the scripts collection, with a much more careful archive design than a simple folder dump.
Maya: The new `phonesync` command reads phone data through ADB and stores records as JSONL: one readable JSON record per line. Images and other binary files remain ordinary files, so you can inspect records with familiar tools and open images in a file browser.
Alex: The archive is scoped to a device ID under `Documents/data/phone-DEVICE-ID`. That helps keep the same provider record IDs from two different phones from colliding, while keeping the format portable.
Maya: The sync updates incrementally, tracks changed records, and uses a manifest to publish a completed run. That manifest is important: if a source fails, the archive should not present a half-finished collection as the latest complete backup.
Alex: The live validation gives this some weight. It migrated 136,743 records and 615 assets from the old SQLite archive in a temporary test, then checked the new archive before retiring the old data.
Maya: The current live archive held 23 JSONL sources, 608 JPEG images, and seven other binary assets. But it did not copy the contents of 58,229 shared files; it stored their inventory only. That distinction matters if someone hears “phone backup” and assumes every file was copied.
Alex: The tests also check that corrupt records, mismatched device identities, and unsafe paths stop the operation instead of being skipped. A failed source is not an invitation to quietly create a tidier but less truthful archive.
Maya: That is the strongest part for me: it is read-only, and the documentation is specific about what it did not test—other Android profiles, other phone models, and recovery after hardware power loss, for example.
Alex: So this is useful, but not a universal phone migration guarantee. The old SQLite-to-JSONL migration was tested, and the records are inspectable; there are still limits on what the phone exposes and what was actually copied.

Maya: Which brings us to a more public kind of shared device: a room full of phones. A live polling tool now lets an audience join by QR code, while the presenter keeps control of the question.
Alex: It runs without its own server, using MQTT over WebSockets to pass messages. The presenter signs control messages with an ECDSA key; the room code is derived from the public key, so the audience link does not carry the private credential.
Maya: That protects the presenter’s controls, but not every part of the system. Anyone can publish to a public MQTT broker, so an attacker could inflate the participant count. The documentation says so plainly.
Alex: The room can save results to a TSV file, and it will not overwrite an existing file just because a presenter clicked Save. To update a file, the presenter must explicitly open it first.
Maya: There’s also a question-seeding format: write `- Question` and put choices two spaces in, one per line. The first question opens immediately; the rest remain in a queue, and malformed lists get line-numbered errors.
Alex: That little format turns a live poll from “think up a question while everyone waits” into something you can prepare. And people can revisit a past question without changing what participants currently see.
Maya: A different group-phone experiment is Pass the Panda. Each phone gets a stable place on a grid that grows from the centre, and people tilt to roll the panda to an adjacent phone.
Alex: Underneath, the code uses a shared tilt sensor, with recentring and screen-orientation handling. If someone drops out or never tilts, the game has timeout, rescue, and flight routes instead of letting the panda get stuck forever.
Maya: The simulations run with 3, 30, and 300 virtual participants. One key check is that at least 95 percent of live phones are visited, while no phone believes it holds the same panda as another phone.
Alex: The route then becomes the artwork: a replayable, downloadable journey with older paths fading in colour. That is a lovely mechanism, but I would still separate a simulation result from a real room of phones on uneven networks.
Maya: Agreed. The tests include busy neighbours, missed phones, late joins, and reconnects. That gives a decent model of trouble, but actual sensor differences and public-broker reliability still need to be checked with people in a room.
Alex: There is also a small design choice in the separate voice-choir experiment: the reported group of about 20 participants had not converged much after 45 seconds of humming. Anand floated a larger test, not a conclusion about who can sing.
Maya: Exactly. One short session cannot show that pitch-matching ability has two distinct groups. But it does turn a hunch into something measurable: try 100 students, record the pitch traces, and see what pattern the data supports.

Alex: In the education platform, the operational work is less playful. An AI judging panel for a drawing game now runs cached model reviews concurrently, rather than paying for the same answer every time the job is retried.
Maya: The judging uses three GPT-6 Luna calls, each with its own shuffled order of the ten options. Results are cached by a key that includes the prompt version, model, drawing image, and option order.
Alex: Concurrency can reach 32, and the runner can stop after a chosen number of batches. More important, it writes each answer to the cache as it arrives, so an interruption does not erase all the useful work.
Maya: The regression test forces one request to fail after some parallel answers have been saved. On the next run, those answers are reused and only the missing ones are asked again.
Alex: That is a much better test than checking only that “parallel” code returns a result. It checks the messy case where one task fails while other calls may already have completed.
Maya: The same platform also extends submission windows for Human Exchange audio and Air Ink drawings. The Air Ink deadline is now 1 November, and Human Exchange audio submissions run through 5 November, with a two-minute upload grace period.
Alex: And the Humans Only results have a clearer private home now: the cached AI judgements and reports are kept together. The documentation warns not to publish student emails or drawings without consent.
Maya: That operational detail is important. A reproducible analysis is useful, but student-created drawings and identities are not automatically public data just because the game produced them.
Alex: Separately, an exam-results endpoint now supports exam-specific admin access. It checks a signed login from the past 24 hours, the requested quiz, and that the account is an administrator for that exact exam.
Maya: That is more constrained than handing out one shared special token. Admins can download full results or copy a `curl` command, while anonymous users still see only public score data.
Alex: The credentials do not go in the URL, and responses are non-cacheable. The tests cover expired and future-dated sign-ins, wrong quiz access, and attempts to reveal a private answer without valid permission.
Maya: There is a useful lesson in how that feature was built: the generated exam metadata now imports the original admin policy function instead of trying to serialize it. Otherwise, its dependencies would disappear in the generated file.
Alex: So the check is not just “does the button appear?” It verifies that the policy survives code generation and is still enforced at the endpoint. That is the right place to test the security boundary.

Maya: The most evidence-heavy story this week is an agent-swarm experiment. Four separate agents shared a directory and a small model budget, but the first four runs produced no useful files.
Alex: Then the fifth run changed the instruction: choose something useful to leave behind, and try to collaborate through the shared directory. In about 100 seconds, the agents made two small projects.
Maya: One was a standard-library Python directory snapshot tool with four tests and a backup playbook. The other was an offline HTML decision matrix, with a guide about uncertainty and sensitivity analysis.
Alex: And collaboration happened through files, not a chat channel. One agent wrote a README, another read it, files were overwritten, a test broke, someone else repaired it, and the group updated the shared notes.
Maya: The measured cost was about 2.7 cents for 83 model requests, out of a one-dollar cap. The tests and a JavaScript syntax check passed, but neither artifact had a full security or functional audit.
Alex: It is tempting to say the instruction caused the difference. But the fifth run changed both the output requirement and the collaboration nudge, and it is still just one run of four agents.
Maya: That is the important limit. The result shows what happened in this setup; it cannot tell us whether a useful-output goal alone would have worked, or whether the collaboration instruction mattered more.
Alex: The next experiment is clear: keep the useful-output goal, remove only the collaboration sentence, and repeat. That is how a compelling story becomes a comparison rather than a victory lap.
Maya: A second evidence-rich source is a new set of living notes from an AI Builders discussion. They separate claims by speaker and timestamp, link them to transcripts and screenshots, and record what was shown versus what was only proposed.
Alex: The notes cover account-specific onboarding, remote 3D control, machine-sound diagnosis, enterprise data context, and incident reports. For example, the machine-sound demo claimed 99.1 and 94.8 percent in two settings.
Maya: But the note also says those figures were not independently reproduced on held-out machines, and that the reported monthly cost depends on assumptions that were not fully stated. That is a useful way to keep a flashy number from becoming a fact without its boundaries.
Alex: The 3D-control idea has a similar split: gesture control of a shared object was demonstrated, but there was lag and missing feedback. Industrial maintenance and remote labs were proposed extensions, not measured outcomes.
Maya: For the incident-report tool, AI-generated causes remain editable hypotheses, and no improvement in investigation time or accuracy was measured. Those distinctions make the notes more useful than a collection of product pitches.
Alex: They also add a careful idea about organizational memory: old code and dashboards may reveal the questions people actually ask of data. But automatically updating an enterprise ontology from that material was discussed as a future capability, not shown working.
Maya: That provenance—the ability to trace an idea back to who said it and what evidence exists—is also what makes the notes maintainable. A claim can be corrected without rewriting the whole story as if it had been certain all along.

Alex: The publishing work puts some of those ideas in front of readers. There are new posts on remote coding, a mobile voice choir, and reading Asterix from a flight by reaching a home computer over Tailscale.
Maya: The remote-coding post describes a practical chain: a home Windows laptop, Remote Desktop Commander, Tailscale, and a sync script to keep work files available. The author used that setup while travelling to draft, code, research, and inspect files from a phone.
Alex: The striking bit is that file sync supplied the missing context: the remote agent could see the course code, transcripts, and projects. It is less like remote desktop as a magic screen and more like bringing your working desk with you.
Maya: But there is an operational footnote: the scheduled remote service was registered to start after reboot, while its network access after a reboot had not yet been verified. Good documentation leaves that uncertainty visible.
Alex: The Asterix experiment adds the browser side of the story. Voice typing on Android, Tailscale access to a laptop in Singapore, and OCR to detect comic panels came together to build a mobile reader with annotations.
Maya: It is a vivid case of an agent joining tools that the author could not configure alone. Still, it depends on the laptop being reachable, the flight Wi-Fi working, and the OCR being good enough for the page. It is a demonstration, not a guarantee of offline reading.
Alex: Another post asks whether adults who used AI for homework would let their children do the same. Of 24 workshop participants who had submitted work, 23 said they used AI; 16 of those would not allow their children to submit AI output.
Maya: That is an interesting mismatch, but it is a small workshop group and a self-reported answer, not a survey of parents. The question exposes a tension between getting work done and believing that a learner should do the work themselves.
Alex: The blog also made two useful publishing changes. Video posters now become listing thumbnails and clickable email previews, and the `llms.txt` page reports the corpus size and top categories instead of top tags.
Maya: Those changes make a large writing archive easier to browse by both people and tools. The new page also links to the source code, while keeping the corpus schema and canonical tags available for machines that need the detail.
Alex: And the Calvin and Hobbes page was rebuilt as a standalone mobile reader: a continuous strip reel, pinch zoom, phrase-first search, and a desktop column layout. That is a substantial product change, not just a new article.
Maya: The implementation keeps the page self-contained instead of wrapping it in the standard blog theme. The point is practical: a phone reader can zoom and pan through strips without fighting a desktop-first page layout.
Alex: There were also two new talk write-ups and a fresh analysis script for an older clinical-trial case study. The script evaluates patient eligibility against inclusion and exclusion criteria using data from several Excel sheets.
Maya: That code is a useful reproducibility artifact, but the supplied change does not tell us its accuracy on a held-out set or whether it was used for a real eligibility decision. We should not infer those results from the presence of a detailed script.

Alex: And, finally, the evaluation tools got a few measured improvements. A mental-math comparison now shows model release dates beside results and keeps the table header visible while scrolling.
Maya: That distinction helps because a test date and a model’s release date answer different questions. The model table can now show the latter without implying the test was run on that date.
Alex: The pricing catalogue was refreshed too. The available change shows 142 rows in the model data being updated, but does not provide the individual price movements, so we should not guess which models became cheaper.
Maya: The point of that catalogue is to compare quality and cost over time, with a Pareto frontier: models that are not beaten by another model on both price and quality. The underlying prices are estimates, not a buyer’s invoice.
Alex: And a new poll feature, a game simulation, and those model comparisons all share one quiet requirement: keep the units and scope clear. A simulated player is not a student; a benchmark score is not a deployment result.
Maya: The conversation keeps coming back to the backup scanner: overlap the scrolls, check that history really loaded, and refuse to call a partial result complete. That is not just a WhatsApp rule; it is a good standard for any automated report.
Alex: Yes. I’d keep two habits from this week: make tools report incomplete work clearly, and test them on a small set of examples you can judge yourself. Thanks for listening.
Maya: And when the evidence is still thin, label the claim as a hypothesis rather than a result. That keeps the next test honest. Goodbye.
