Alex: Anand's Weekly Codecast. Week ending 04 October 2026. This week, a recurring question was: how do you make a useful system behave well when the world gets messy?
Maya: And the answer was often less glamorous than a new model: preserve the evidence, make failure visible, and give people a way to recover. That showed up in tools Anand uses every day.
Alex: Take the call-transcription tool. It was substantially rebuilt around durable, exact-request caches, raw model responses, cumulative timestamps, and a private diagnostic folder for each run.
Maya: The benchmark is a useful check on the temptation to optimize only for price. Cheaper thinking roughly halved the measured bill, but the five short recordings also had more unsupported names, boilerplate, summaries, and omissions.
Alex: So production defaults stayed put. Two small fixes did make it in: absorb up to one second past a chunk boundary, and keep valid transcript text before a bad timestamp instead of throwing away the whole paragraph.
Maya: That second fix avoids a paid retry. In a replay test, the saved raw response yielded the valid text with zero API calls. The continuation remains in the logs, so the repair doesn’t erase evidence of what went wrong.
Alex: There was a similar lesson in the local MCP server. A UTF-8 probe ended in the middle of a multibyte character, so a normal decode falsely rejected a valid file. An incremental decoder now waits for the next bytes.
Maya: And genuinely invalid UTF-8 still fails clearly. Tests cover both cases. The connection wrapper also gained a watchdog: check the secure tunnel every ten seconds, and recreate it with the same ID if control-plane health has been missing for 90 seconds.
Alex: For browser work, new `edge js` and `edge cdp` commands use a page’s `webSocketDebuggerUrl` directly. They can evaluate JavaScript or send raw Chrome DevTools Protocol commands without activating the tab.
Maya: The target resolver prefers an exact title, URL, or ID, and refuses ambiguous partial matches. That safeguard matters when the browser is already in use. Separate fixes reject contaminated WhatsApp backup JSONL before connecting, and make test paths work under any home directory.
Alex: Even the music queue got a bit more considerate. With no song supplied, it can start from VLC history, decode escaped filenames, and skip the last 30 unique tracks; `--avoid-recent 0` turns that off.
Maya: And `--next` queues recommendations without keeping the shell busy. It’s a modest utility, but the design is recognizably the same: infer the user’s likely intention, while leaving a simple switch when the default is wrong.

Alex: That balance between convenience and control also shaped FollowThrough, the action tracker in the software-delivery demo. It grew from a small local app into something that can show a whole development process.
Maya: The everyday features now include CSV import and export, weekly recurrence, bulk owner reassignment, and pagination. Long lists show 20 actions per page; browser tests check a 24-action search result and confirm the second page contains four.
Alex: The CSV path has some thoughtful edges. Exports prefix formula-like values with an apostrophe, so spreadsheet software is less likely to execute them. Imports parse the entire file before writing anything, so malformed CSV can’t leave a valid-looking partial import.
Maya: A well-formed file can still contain bad rows: those are reported individually, while valid rows are imported. That distinction is practical. A user shouldn’t lose all their good work because one title is blank, or be left unsure what actually got saved.
Alex: The action history is also more complete now. Changes to status, owner, priority, notes, and source can be retrieved through the history API and labelled in the interface. A priority change from low to high has a specific regression test.
Maya: That history is not just decoration; otherwise a handoff can look like a change with no explanation. Duplicate capture now prompts before adding a near-identical title, but still allows the user to create another one deliberately.
Alex: And for the larger list, filtering resets pagination to page one and the page count is clamped if actions disappear. Those are the tiny state transitions that turn a feature from “works in the demo” into something less surprising.
Maya: The wider demo now runs across ten sprints, not five. Its orchestration code can resume one persona’s discovery without losing earlier candidates, closes stdin for spawned agents, and sets timeouts for work such as a 15-minute development run.
Alex: It also logs model-token usage and estimates cost by call. For GPT-6 Luna, the recorded rates are ten cents per million uncached input tokens, one cent for cached input, and fifty cents for output.
Maya: Those are rate-card estimates, not a claim about anyone’s bill. A new Time Machine replays ten sprints from event and cost logs. Where a historical development start wasn’t recorded, the visual transition is marked as derived rather than passed off as observed.
Alex: That distinction feels important. A polished replay can make a story look more certain than its source data. Here, the app’s own evidence trail is part of the demonstration, including a review that catches an issue before it is accepted.
Maya: And the changes are testable in practice: the smoke test checks large-list navigation, duplicate confirmation, and the narrow-screen layout. It’s a small simulated product, so it does not prove real-world productivity savings—but it does expose the mechanism.

Alex: Evidence was also the point of a new evaluation project, rather than a claim that smaller models are suddenly equivalent to frontier ones. The benchmark freezes 100 financial questions from FinQA, with a reproducible sample and a separate answer scorer.
Maya: It filters out cases where the dataset’s written answer conflicts with its executable answer, then stores the case hash and sampling method. The model sees the question and selected evidence, not the original reasoning program or full report.
Alex: That benchmark was built to compare local-capable models with GPT-6 Luna under constraints like privacy and local execution. The work this week establishes the test harness and frozen data; it does not provide a finished scorecard yet.
Maya: That’s worth saying plainly. A benchmark framework is not a benchmark result, and a hundred questions are still a small sample. But the frozen cases make future comparisons more useful than changing the test set each time.
Alex: A separate three-task coding-agent comparison did have a result. On an 8-gigabyte GPU, Qwen 3.6 was the stronger local choice over Gemma 4 E4B, but GPT-6 Luna did best on all three tasks.
Maya: The tasks were concrete: image loading, backup-file integrity, and console-log readability. Gemma failed to complete two tasks, and its console change still failed four tests. Qwen made useful attempts, but also timed out or left failing tests.
Alex: Luna’s image fix was notably simple: native `loading="lazy"` and `decoding="async"`. The browser already requested each repeated image URL only once; the actual problem was that all 24 images loaded eagerly and competed on a slow connection.
Maya: That’s a good example of inspecting the mechanism before “optimizing” it. The benchmark is about agents with their tools, not just model quality: Codex could use browser tools, while the local agents ran through different setups.
Alex: There’s also a 77-case BANKING77 classification pilot, now with GPT-6 Luna among ten general models. It got 60 of 77 correct, about 78 percent, while reporting average confidence of about 92 percent.
Maya: That gap is the practical warning. Confidence can help rank which answers deserve review, but it is not automatically a trustworthy probability. On 77 examples, no one should treat a threshold as a production guarantee.
Alex: The reported cost was about 0.43 cents for all 77 Luna cases. But the write-up also notes that 17 errors remain, and that some cases need the actual support-routing definitions, not just the intent labels.
Maya: Meanwhile, the model-pricing chart refreshed its leaderboard data, and the art-style gallery kept its image pipeline explicit: small tracked WebP thumbnails for the grid, larger WebPs in releases for zoom, and medium-quality GPT Image 2.5 Flare generations.
Alex: That gallery had a real deployment bug: for Flare, the thumbnail and full-size image were the same file. The fix separates those paths again. It’s a reminder that compression and previews are not merely build details; they change what a visitor sees.

Maya: The most elaborate evidence work this week was an image-history investigation. It captured 73 revisions, 60 distinct images, and 1,309 labeled regions from a Google image-editing session, then built an interactive slideshow of how the images changed.
Alex: The lineage question was harder than “which image came before this one?” A later upload can have been generated much earlier, and similar images can be siblings, not parent and child. So the analysis filtered candidates by time and ranked visual matches.
Maya: It used SIFT feature matches as the main signal, with SSIM as supporting evidence. Across 60 controlled edits, the chosen method retrieved the known parent first in 57 cases and in its top five in all 60.
Alex: That sounds strong until we say what it does not mean: it is not a measured probability that a parent is correct. The original generation prompt and source-image identity were not exposed, so the gallery labels these as inferred candidates.
Maya: And there are explicit exceptions. Eight revisions reuse old images, three revisions had no image operation, and one image operation had no downloadable image. The interface keeps those events visible instead of inventing missing pictures or edges.
Alex: The slideshow also protects people’s names: it displays first names only. Its descriptions are editorial titles keyed by exact timestamp and asset ID, so renumbering the history—or returning to an old image—doesn’t attach the wrong title.
Maya: That’s a lot of care for a visual project, but it makes the result more honest. The comparison of detected objects is labelled as automatic observation, not as a recovered prompt or a reliable account of every pixel-level change.
Alex: A very different image problem turned into a useful personal software patch. VLC’s playlist does not support the Composer field, which matters when you have about 1,200 Tamil, Hindi, and Telugu songs tagged by composer.
Maya: The first attempt asked for Album Artist, which is a different field. After spotting that mismatch, the patch added Composer to VLC 3.0.24. The post describes a working build after a few rounds of guidance, but that is one person’s machine, not an upstream release.
Alex: So the two image stories share a nice contrast: one infers what cannot be observed directly and labels uncertainty; the other changes a known piece of software to reveal a field the interface left out.
Maya: And in both cases, knowing the data model matters. “Looks similar” is not proof of image ancestry; “artist” is not the same metadata as “composer.” The small naming distinctions make a large difference to the result.

Alex: A lot of operational work this week was about moving Cloudflare projects from Wrangler to the newer `cf` CLI without changing the things that matter underneath.
Maya: For the exam platform, that meant replacing the old configuration while preserving production and development Worker names, SQLite-backed Durable Objects, their classes, and separate storage buckets. Tests check the daily production schedule and that development has no cron.
Alex: The new configuration also pins the entry point and compatibility date, and moves secrets and bindings into typed configuration. There are extra tests for self-paced exam windows—including zero, negative, empty, and user-dependent hour limits.
Maya: Those tests matter because a migration can compile and still accidentally change who can start an attempt. The change also adds discussion links for many new questions and runs lint over the expanded question set.
Alex: A network-games service made the same CLI move, with typed D1 and KV bindings and updated Node requirements. Its older game APIs now sit alongside target-free visual games, including Tangram, Jigsaw, and a three-dimensional brick-building task.
Maya: The visual framework has reusable contracts for state parsing, canonicalization, runtime, authoring, and grading. Browser clients can expose WebMCP tools when the browser supports them. But these attestations sign a captured state; the server does not verify a hidden target arrangement.
Alex: That limitation is important: a signed receipt proves what state was submitted, not that a student solved a puzzle. It is useful infrastructure for consistent records, but it shouldn’t be mistaken for automatic proof of correctness.
Maya: AI Pipe also moved to `cf`, preserving its SQLite Durable Object and domain configuration. Alongside that, it added GPT-6 Luna pricing and tests for the OpenAI Responses API and OpenRouter reasoning options.
Alex: The pricing entry is $0.10 per million input tokens and $0.50 per million output, with tests checking the exact usage charge. That’s the kind of detail a proxy must get right: a model can respond correctly while billing users incorrectly.
Maya: Across all three migrations, Wrangler remains in the build or test plumbing where needed; `cf` owns the deploy and configuration path. So this is not a clean break from the old ecosystem, but a staged change with compatibility tested.

Maya: In a portfolio demo, a customer-type filter was added only to relevant stages. A follow-up checked whether non-selected customer types still stood out in the plots; the implementation now removes or fades those points instead of leaving the filter looking cosmetic.
Alex: And research around conference proposals produced a useful test question: if a benchmark scores 100 percent when a model has stopped calling tools, is the metric measuring capability or silence? One proposal had 60 examples where a result did not always hold.
Maya: The underlying lesson was to separate observation from generalization. Another proposal reported that a final checkpoint could be about 25 times more damaged by compression than a mid-training checkpoint, while its likely causes—over-training and learning-rate decay—were still confounded.
Alex: That is not just an interesting number; it tells the audience what remains unknown. And an assessment log captured another kind of limit: the user completed the test, but the site showed no numeric score, so the record says exactly that.
Maya: The assessment notes also preserve failures. One SQL test failed; a coding grader rejected output formatting even where the algorithm looked plausible. The lesson for future attempts is to inspect the actual expected-versus-actual output, including whitespace, rather than declare victory from reasoning alone.
Alex: That evidence-first habit also shaped a living knowledge base for AI Builders. It now has a clear chain—session, atomic claims, reusable notes—and a guide for preserving who said what, when, and with what evidence.
